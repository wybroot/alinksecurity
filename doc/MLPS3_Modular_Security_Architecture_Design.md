# 等保 2.0 三级模块化安全组件矩阵与统一安全管理中心技术架构设计方案

---

## 1. 项目定位与核心设计哲学

### 1.1 背景与目标
针对中国《网络安全等级保护基本要求》（GB/T 22239-2019，即**等保 2.0 三级**），本方案旨在打造一套**高度解耦、自由选配、专机专用轻量 Agent、顶层统一纳管**的企业级安全产品矩阵。

该方案适用于私有云、混合云及物理服务器集群环境，既能作为企业内部过等保的自研安全基础设施，又具备商业化 ToB 交付的灵活性。

### 1.2 核心设计哲学
1. **乐高积木式解耦（组件独立成军）**：
   - 拒绝“臃肿全家桶单一 Agent”，每个安全组件（云 WAF、云防火墙/微隔离、EDR、日志审计、数据库审计等）均拥有独立的架构、独立的数据流、以及**专用的轻量化微 Agent/探针**。
   - 单个组件或 Agent 异常崩溃，绝对不影响其他组件与业务系统运行。
2. **商业选配自由（按需装配）**：
   - 客户缺什么就采购/部署什么。客户若已采购硬件防火墙，只需单独部署日志审计或 EDR；若为全新集群，则一键勾选全套组件。
3. **顶层统一纳管（一个中心大脑）**：
   - 所有独立安全组件均通过标准化 OpenAPI 与事件总线接入**自研安全管理中心**。
   - 管理中心统一实现等保三级强制要求的**三权分立**（系统/安全/审计管理员）、**双因子认证（2FA）**、**全局资产态势感知**与**180天合规日志归档**。
4. **最大化复用权威开源底座**：
   - 绝不从零编写底层协议分析器、日志引擎或内核驱动；充分吸纳业界顶级开源项目的技术精华，重点研发“胶水层、统一纳管接口、控制台与等保合规规则对齐”。

## 4. 关键独立组件详细设计与开源改造指南

### 4.1 云 WAF 组件 (独立组件)
* **开源基石**：`chaitin/safeline` (长亭雷池) 或 `corazawaf/coraza`。
* **业务定位**：负责阻断 HTTP/HTTPS 层的应用攻击（OWASP Top 10、Webshell、0day 攻击注入）。
* **形态设计**：
  * **集群反向代理模式**：针对公网入口服务器，部署独立 WAF 节点接收公网流量。
  * **Sidecar/本地 Agent 模式 (`waf-agent`)**：作为 Nginx 动态模块或本地轻量代理，实时拉取管理中心的防护规则，遇到本地阻断事件时异步将告警推给管理中心。
* **等保得分项**：对标 8.1.3.3 条款（提供应用层访问控制与应用入侵防范）。

### 4.2 云防火墙与东西向微隔离组件 (独立组件)
* **开源基石**：`cilium/cilium` (基于 eBPF) + Linux `nftables` / `iptables`。
* **专用探针 (`cfw-agent`)**：
  * 采用 Go 编写的极小守护进程（静态编译大小 < 10MB，内存 < 15MB）。
  * 负责监听管理中心下发的“安全域与端口黑白名单”。
  * 底层调用 Linux 内核的 `netfilter / nftables` 原生接口下发阻断规则，零用户态性能损耗。
* **功能特性**：
  * **微隔离**：禁止非 Web 节点直接访问核心业务端口，禁止普通应用节点直接连入数据库管理端口。
  * **异常外联阻断**：检测并阻断受害机器主动向境外或恶意 IP 发起 TCP/UDP 连接。
* **等保得分项**：对标 8.1.3.1 条款（安全区域边界访问控制，细粒度到协议、端口、源目地址）。

### 4.3 主机安全 / EDR 组件 (独立组件)
* **开源基石**：`bytedance/elkeid` (推荐，性能更优) 或 `wazuh/wazuh`。
* **专用探针 (`edr-agent`)**：
  * 主体使用 Rust 或 Go 编写，运行在 Linux 内核之上（利用 eBPF 或 auditd 子系统）。
  * **进程行为捕获**：监控 `execve`、`connect`、`ptrace` 等高危系统调用。
  * **恶意脚本检测**：集成反弹 Shell 识别算法与 Webshell 静态/动态特征引擎。
  * **主动防御联动**：检测到高危入侵进程时，提供毫秒级 `kill -9` 终止进程并封禁攻击源 IP。
* **等保得分项**：对标 8.1.4.3 / 8.1.4.4 条款（主机防恶意代码与入侵检测）。

### 4.4 综合日志审计系统 (独立组件，核心合规底线)
* **开源基石**：`vectordotdev/vector` (Agent 探针) + `ClickHouse/ClickHouse` (存储底座)。
* **专用探针 (`log-agent`)**：
  * 基于 Vector 裁剪，移除非必要的输入输出插件，只保留 Syslog、文件读取、Journald 与 gRPC 模块。
  * 内存开销严格限制在 10MB 以内，CPU 占用率低于 0.5%。
  * 本地设置 50MB 环形磁盘缓存，网络短时间中断时不丢日志。
* **服务端与合规生命周期机制**：
  * **180 天存储策略**：配置 ClickHouse 的 TTL（Time-To-Live）自动生命周期淘汰策略，明确设定 `>= 180 天`。
  * **完整性校验（防篡改）**：按天对归档日志数据块计算 SHA-256 哈希指纹，并写入专用防篡改审计账本中，确保测评时可校验日志原貌。
* **等保得分项**：对标 8.1.4.2 条款（日志留存 180 天以上，覆盖重要节点与用户操作）。

### 4.5 数据库审计系统 (独立组件)
* **开源基石**：基于 `cilium/tetragon` 或 `sysstat/sysdig` 的 eBPF 抓包能力二次封装。
* **专用探针 (`dbaudit-agent`)**：
  * 仅部署在包含数据库（MySQL / PostgreSQL / Oracle / Redis）的机器上。
  * 在内核态过滤 TCP 目标端口（如 3306），将通信数据包复制到用户态进行 SQL 协议编解码。
* **审计与风险分析能力**：
  * 记录所有 SQL 执行语句、执行人、客户端 IP、影响行数。
  * 实时检测高危行为：批量 `DELETE` 无 `WHERE` 条件、`DROP TABLE`、大批量敏感数据导出等，并触发高危红色告警。
* **等保得分项**：对标 8.1.4.2 条款（业务数据库操作独立审计）。

### 4.6 网页防篡改系统 (独立组件)
* **技术实现**：
  * 基于 Linux 内核 `fanotify` 机制编写专用探针 `tamper-agent`。
  * 当黑客试图上传 WebShell 或修改网站静态文件（html、js、php 等）时，内核态直接拦截写操作。
  * **秒级自愈机制**：探针本地维护一份只读签名的干净源镜像，一旦检测到任何非受信任的变更，1 秒内自动覆盖还原。
* **等保得分项**：对标 8.1.4.6 条款（重要数据完整性保护）。

## 5. 统一安全管理中心 (大脑) 核心功能设计

安全管理中心是整个系统的总指挥所，依据等保 2.0 三级第 **8.1.5 条（安全管理中心）** 严格设计。

### 5.1 等保“三权分立”权限矩阵（必查考核项）
管理中心严禁存在一个拥有所有权限的超级管理员（Admin），必须强制拆分为三个相互独立、相互制约的内置角色：

| 角色名称 | 允许的操作权限 | 绝对禁止的操作权限 | 测评演示要点 |
| :--- | :--- | :--- | :--- |
| **系统管理员 (Ops Admin)** | 纳管服务器资产、配置组件网络、下发/重启 Agent、查看系统软硬件资源状态。 | **严禁**配置安全策略（如添加防火墙白名单）；<br>**严禁**查看与导出审计日志。 | 登录系统管理员账号，界面上隐藏安全规则配置入口与审计日志菜单。 |
| **安全管理员 (Sec Admin)** | 制定与下发 WAF 防护策略、配置防火墙隔离规则、配置 EDR 查杀黑名单、管理漏洞扫描任务。 | **严禁**添加系统运维用户；<br>**严禁**删除或查看详细系统操作审计日志。 | 登录安全管理员账号，能调策略但无法新建账号，无法清理日志。 |
| **审计管理员 (Audit Admin)** | **只读**查看全网所有审计日志（包括系统管理员和安全管理员的一切操作记录）、导出等保审计报告。 | **严禁**进行任何系统配置与策略修改；<br>**严禁**删除、清空或篡改审计记录。 | 登录审计管理员账号，全站所有“保存、删除、编辑”按钮均不存在，仅保留“查询、导出”功能。 |

### 5.2 双因子认证（2FA / MFA）
* 后台采用开源 **Casdoor** 作为身份网关。
* 任何管理员登录，必须输入：`账号 + 强密码 (长度>=8位，含大小写字母、数字与特殊字符)`，随后强制校验 **手机短信验证码** 或 **Google Authenticator (TOTP) 6位动态口令**。
* 密码输入错误达 5 次自动锁定账号 30 分钟。

### 5.3 一键自由选配安装脚本生成引擎 (ToB 交付核心)
在管理中心的“主机资产纳管”界面，管理员勾选目标服务器的角色和所需组件：

* [x] 日志审计 (`log-agent`)
* [x] 主机安全 EDR (`edr-agent`)
* [ ] 数据库审计 (`dbaudit-agent`)
* [x] 网页防篡改 (`tamper-agent`)
* [ ] 云防火墙微隔离 (`cfw-agent`)

**生成对应的一键安装脚本**：
```bash
curl -sSL https://soc.yourdomain.com/api/v1/agent/install.sh | \
  bash -s -- \
  --server=https://soc.yourdomain.com \
  --token=SEC_TOKEN_ABC123 \
  --components=log,edr,tamper
```
脚本执行逻辑：
1. 本地创建独立目录 `/opt/your-sec/`。
2. 按需下载 `log-agent`、`edr-agent`、`tamper-agent` 的独立二进制包。
3. 分别注册并启动各自的 Systemd 守护单元（`sec-log.service`, `sec-edr.service`, `sec-tamper.service`）。
4. 各 Agent 使用相同的 Token 接入管理中心，但在主机上各占各的独立进程与资源配额。

### 5.4 等保合规报表一键生成引擎
管理中心内置“等保 2.0 三级自检模版”：
* 定期汇总：
  1. 当前全网日志已连续留存天数（核验是否 $\ge 180$ 天）；
  2. 三权分立登录与审计记录表；
  3. 主机弱口令与基线扫描达标率；
  4. 过去 6 个月拦截的高危入侵与 SQL 攻击事件总结。
* 一键导出标准化 PDF/Excel 报告，等保测评老师进场时可直接打印移交。

## 7. 方案总结

本方案彻底抛弃了传统“单 Agent 全家桶”的笨重缺陷，在**架构解耦、轻量可靠、选配灵活**的同时，百分之百对齐了中国等保 2.0 三级的规范要求：
- 依靠 **Vector + ClickHouse** 攻克 180 天日志审计死线；
- 依靠 **Elkeid/Wazuh** 与 **Safeline WAF** 构筑主机和边界纵深防御；
- 依靠 **JumpServer** 稳稳拿下运维审计与访问控制最高分；
- 依靠 **Casdoor + 自研安全管理中心** 建立稳固的“三权分立、双因子与集中管控”中枢神经。

各组件均基于经过实战检验的权威开源底座，研发团队只需专注在**管理中心协议适配、安装分发自动化和等保规则对齐**上，能在最短周期内打造出一套自主可控、极具竞争力的企业级等保安全产品体系。
