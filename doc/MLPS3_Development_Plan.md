# 等保 2.0 三级模块化安全组件矩阵与统一安全管理中心详细研发计划

---

## 1. 计划概述与研发目标

### 1.1 研发目标
本计划旨在指导团队按照**等保 2.0 三级（GB/T 22239-2019）**要求，在 16 周（约 4 个月）内，基于业界成熟开源技术底座，自研一套**高内聚低耦合、按需选配、多独立轻量 Agent、顶层统一纳管**的企业级安全矩阵平台。

### 1.2 团队配置假设（敏捷核心小团队）
* **架构师 / 后端主导（1 人）**：负责全局架构、统一安全管理中心控制面、Casdoor 认证对接、OpenAPI/NATS 规范。
* **底层系统与安全开发工程师（1 人）**：负责 Linux Agent（Go/Rust）、eBPF 探针、nftables 微隔离规则、WAF/EDR 策略适配。
* **前端全栈工程师（1 人）**：负责安全管理中心 Web 控制台、等保大屏、三权分立动态鉴权、可视化图表。
* **测试与 DevOps 工程师（0.5~1 人）**：负责多节点测试集群管理、跨平台 CI/CD 编译打包、红蓝对抗压测与等保模拟自检。

## 3. 分阶段详细研发任务与里程碑

### 阶段 0：工程基座搭建与通信协议标准化（第 1 周）

#### 目标
统一各独立组件与安全管理中心的**接口规范、数据格式、通信协议**，完成 CI/CD 跨平台打包体系与测试靶场搭建。

#### 核心任务
1. **接口规范与通信标准制定**
   - 确定 Agent 与管理中心、各独立组件服务端与管理中心的通信标准：统一采用 `gRPC (mTLS 双向加密)` 与 `RESTful / OpenAPI 3.0`。
   - 定义统一安全事件标准 JSON Schema：
     - 基础元数据：`event_id`, `timestamp`, `source_component`, `host_ip`, `severity`, `threat_type`, `payload`。
2. **轻量高性能消息总线部署**
   - 搭建 **NATS Server** 集群，定义各组件事件发布与订阅的 Topic 规范（例：`sec.event.waf.*`、`sec.event.edr.*`、`sec.event.audit.*`）。
3. **靶场环境与自动化构建**
   - 搭建 5 台虚拟机构成的测试集群（模拟 Web 边界区、业务应用区、核心数据库区、统一管理区）。
   - 配置 GitLab CI / GitHub Actions 跨平台自动化编译流水线，支持目标平台：CentOS 7/8/9、Ubuntu 20/22、Rocky Linux（x86_64 与 ARM64）。

#### 里程碑交付物
* ✅ 输出《统一安全事件与控制面通信协议规范 v1.0》。
* ✅ 完成 Agent 自动化跨平台交叉编译与 RPM/DEB 基础打包脚本。

### 阶段 1：安全管理中心控制面与独立日志审计系统【合规红线 MVP】（第 2 ~ 5 周）

#### 目标
攻克等保 2.0 三级最容易被一票否决的两大核心红线：**“三权分立 + 2FA”** 与 **“全网日志留存 $\ge$ 180 天且防篡改”**。该阶段完成即可交付第一版最小可行性产品（MVP）。

#### Sprint 1（第 2 ~ 3 周）：管理中心底座与三权分立鉴权体系
* **后端研发**：
  - 集成开源 **Casdoor** 作为统一 IAM / SSO 身份网关。
  - 构建**三权分立**底层 RBAC 权限引擎：
    - **系统管理员 (Ops Admin)**：仅限资产纳管、网络与组件配置、进程状态监控；**严禁**配置安全防护策略与查看审计日志。
    - **安全管理员 (Sec Admin)**：仅限下发安全策略、配置规则白名单、管理漏洞扫描；**严禁**创建系统用户与查看审计日志。
    - **审计管理员 (Audit Admin)**：拥有独立全站审计只读权限，专职查看系统管理员与安全管理员的操作日志；**严禁**进行任何系统配置。
  - 强制开启 **2FA 双因子认证**（TOTP 动态密码卡，支持 Google/微软 Authenticator 及手机短信）。
* **前端研发**：
  - 构建安全管理中心 Web 控制台框架（React / Vue + Arco Design）。
  - 根据登录角色动态渲染菜单权限，严格在前端与接口层双重隔离互斥操作。

#### Sprint 2（第 4 ~ 5 周）：独立综合日志审计组件 (`log-agent` + ClickHouse)
* **专用 `log-agent` 研发**：
  - 基于开源 **Vector** 裁剪精简内核，移除非必要模块，打造极轻量独立二进制。
  - 采集源支持：`/var/log/secure`、`/var/log/audit/audit.log`、Nginx access 日志、系统 journald。
  - 资源限制：通过 systemd 内置 cgroups 严格限制内存上限 20MB、CPU 占用 < 1%。
* **日志审计服务端与合规存储**：
  - 部署 **ClickHouse** 列式存储引擎，设计按天分区的日志表结构。
  - **180 天生命周期（TTL）**：配置数据保留策略强制 `>= 180 天`。
  - **防篡改机制**：每日凌晨对归档日志数据块计算 SHA-256 哈希链，写入防篡改校验表。
* **管理中心纳管集成**：
  - 提供日志多维检索、全文搜索、关键字过滤、等保 180 天留存审计证明报表导出。

#### 里程碑交付物
* ✅ 现场通过三权分立登录权限测试，三个角色权限互斥无交集。
* ✅ `log-agent` 成功将测试节点日志加密推入 ClickHouse，内存占用稳定在 15MB 左右。
* ✅ 达成等保 2.0 三级“安全审计”条款硬性要求。

### 阶段 2：主机安全 EDR 与运维堡垒机整合（第 6 ~ 9 周）

#### 目标
解决等保 2.0 三级“计算环境恶意代码防范、入侵防范与运维特权访问控制”条款。

#### Sprint 3（第 6 ~ 7 周）：独立 EDR 系统 (`edr-agent` + 威胁分析服务)
* **专用 `edr-agent` 研发**：
  - 基于 **Elkeid** 核心轻量 Agent 架构或 Linux `auditd` 框架二次开发。
  - **暴力破解防护**：实时监听 SSH 登录失败事件，同一 IP 连续失败 5 次自动触发本地 `iptables` 临时封禁 1 小时，并上报事件。
  - **反弹 Shell 检测**：监听文件描述符重定向事件，精准识别 `bash -i >& /dev/tcp/...` 等经典反弹行为。
  - **Webshell 动态检测**：监听 Web 目录下的进程派生行为（如 `nginx`/`httpd`/`php-fpm` 启动 `sh`/`python`/`whoami`）。
* **EDR 策略中心与响应引擎**：
  - 服务端维护黑白名单策略库，支持一键下发“阻断 / 仅告警”指令。
  - Agent 收到阻断指令毫秒级执行 `kill -9` 并隔离可疑可执行文件。

#### Sprint 4（第 8 ~ 9 周）：堡垒机对接与多 Agent 选配生成器
* **独立堡垒机组件标准化集成**：
  - 将开源 **JumpServer** 作为标准运维跳板网关纳入整体方案。
  - 打通统一 SSO：管理员只需登录安全管理中心即可免密直达堡垒机，强制收敛所有 SSH/RDP 运维流量。
  - 管理中心通过 JumpServer API 读取会话审计记录、高危拦截记录与录像索引。
* **主机端“选配一键安装生成器”研发**：
  - 在管理中心实现脚本模板引擎，根据管理员勾选组件动态生成命令：
    `curl -sSL https://soc.yourdomain.com/install.sh | bash -s -- --token=xxx --enable=log,edr`
  - 脚本自动拉取对应二进制、注册各自独立的 Systemd 服务（`sec-log.service`, `sec-edr.service`）并保障相互独立。

#### 里程碑交付物
* ✅ 模拟 SSH 暴力破解与反弹 Shell 攻击，`edr-agent` 成功识别并自动阻断。
* ✅ 一键脚本可以在纯净系统上按需装配选配组件，单进程崩溃不影响其他 Agent。

### 阶段 3：边界安全、网络微隔离与数据安全组件（第 10 ~ 13 周）

#### 目标
补齐等保“安全区域边界”与“核心业务数据库审计”各项独立能力。

#### Sprint 5（第 10 ~ 11 周）：云 WAF 与云防火墙/东西向微隔离
* **云 WAF 组件集成**：
  - 接入 **长亭雷池 (Safeline)** 或 **Coraza WAF** 作为边界防护节点。
  - 研发轻量控制探针 `waf-agent`：负责自动同步管理中心配置的拦截白名单与域名配置，异步上报 SQLi、XSS、Webshell 阻断日志。
* **东西向微隔离组件 (`cfw-agent`)**：
  - 使用 Go 编写轻量微隔离探针，底层直接调用 Linux `nftables`。
  - 核心功能：
    - 管理中心定义服务器安全域（DMZ区、业务区、数据区）。
    - 下发微隔离策略（例：禁止业务区除指定 IP 外的任何机器访问数据库 3306 端口）。
    - 探针本地执行原子规则更新，确保网络规则变更不丢包。

#### Sprint 6（第 12 ~ 13 周）：数据库审计系统与网页防篡改
* **独立数据库审计系统 (`dbaudit-agent`)**：
  - 基于 eBPF/AF_PACKET 零拷贝监听网络包，对 MySQL/PostgreSQL 协议进行旁路解码。
  - 记录客户端来源、账号、SQL 文本、执行耗时；高危 SQL（如 `DROP TABLE`、无条件 `DELETE`）立即标记红级告警送回中心。
* **网页防篡改探针 (`tamper-agent`)**：
  - 基于 Linux `fanotify` 机制实现目录监控。
  - 当受监控的静态资源目录被未授权修改时，立即拦截写请求，并从备份缓存区秒级恢复。
* **脆弱性检查与等保基线模块（无常驻 Agent）**：
  - 集成 **Trivy** 离线漏洞库 + 自研等保基线检查脚本（检查空密码、文件权限、SSH 配置）。
  - 按需下发执行，扫描完毕生成报告后进程自动退出，不占任何常驻内存。

#### 里程碑交付物
* ✅ 模拟 SQL 注入被 WAF 成功拦截并回传告警到管理中心。
* ✅ 在核心数据库节点验证 `dbaudit-agent` 旁路抓包无性能损耗（QPS 损失 < 3%）。
* ✅ 恶意篡改网页文件被秒级自愈并告警。

### 阶段 4：态势聚合、等保合规报表引擎与预测评验收（第 14 ~ 16 周）

#### 目标
系统串联、端到端全链路闭环，达到可直接邀请等保测评机构进场打分的商用状态。

#### Sprint 7（第 14 ~ 15 周）：态势感知大屏与合规报表引擎
* **安全管理中心态势大屏**：
  - NATS 事件统一汇聚引擎：将 WAF、EDR、数据库审计、防火墙的告警标准化归一。
  - 可视化展示：集群拓扑健康度、攻击源 IP 地图、告警等级分布、180 天日志存储水位。
* **《等保 2.0 三级合规自检报告》一键导出**：
  - 内置等保三级控制点映射字典，系统自动计算合规得分：
    - 身份鉴别合规度（2FA、口令复杂度）
    - 访问控制合规度（微隔离策略、三权分立）
    - 安全审计合规度（ClickHouse 留存天数 $\ge 180$ 证明）
    - 入侵防范合规度（WAF、EDR、基线达标率）
  - 一键导出规范格式的 PDF / Excel 测评证据报告。

#### Sprint 8（第 16 周）：红蓝对抗、性能压测与预测评演练
* **高可用与极限压测**：
  - 模拟单个 Agent 内存爆满被 OOM 杀死，验证守护进程（Systemd）自动恢复，且其他 Agent 零影响。
  - 模拟大并发流量冲击，验证管理中心 NATS 与 ClickHouse 吞吐稳定性。
* **模拟等保机构测评与渗透**：
  - 逐条对照 GB/T 22239-2019 第三级核查表，进行自检与攻防验证。
  - 消除自研控制台存在的潜在 Web 漏洞（XSS、CSRF、越权等）。

## 4. 核心质量与风险控制策略

| 潜在风险项 | 风险等级 | 预防与应对方案 |
| :--- | :---: | :--- |
| **Agent 相互干扰或拖垮业务** | **高** | 1. 严格使用 Systemd 的 `MemoryMax` 与 `CPUQuota` 做物理资源硬限制；<br>2. 每一个 Agent 配置独立的 Watchdog 与工作目录，严格做到互不信任、故障隔离。 |
| **等保测评老师对自研系统不信任** | **中** | 1. 界面功能名称与布局严格使用等保标准国标术语；<br>2. 提前准备完备的《自研系统安全性与防篡改白皮书》及第三方代码审计报告。 |
| **ClickHouse 180 天日志存储爆盘** | **中** | 1. 采集端进行白名单过滤与结构化压缩；<br>2. 服务端开启 ZSTD 高比例压缩算法；<br>3. 建立 80% 磁盘容量水位告警与冷热数据异地对象存储归档机制。 |
